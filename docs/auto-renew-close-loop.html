证书自动续期闭环

DNS 解析在阿里云 · 入口负载在阿里云 ALB · DNS-01 验证

一、一条链，没有人

计划任务每天唤醒一次，判断剩余天数；只有临期才进入签发与部署。中间的箭头没有一处需要人接手。

二、15 天窗口

90 天有效期的前 75 天，计划任务只是读文件然后退出。进入最后 15 天后，它才第一次真正动手。

三、失败时线上是什么状态

自动化最该讲清楚的不是顺利时多快，而是出错时会留下什么。

先签后换（本工具）

  • 签发成功之前，线上证书不动
  • 签发失败 → 监听仍用旧证书，用户无感
  • 部署失败 → 证书已在盘上，可单独补跑部署
  • 15 天窗口内可以失败很多次

先删后传（常见做法）

  • 先移除旧证书，再上传新的
  • 上传失败 → 监听无证书，直接空窗
  • 空窗期内所有 HTTPS 访问报错
  • 只能靠人盯着恢复

四、闭环成立的三个条件

  • 域名 NS 指向阿里云云解析
    注册在阿里云但 NS 指向别家，云解析 API 看不到那些记录。
  • 入口负载是阿里云 ALB
    证书挂在哪里，决定部署脚本往哪写。
  • 使用 DNS-01 验证
    ALB 七层终止 TLS，证书未配好前 80 端口回源路径是断的；泛域名只能用 DNS-01。
